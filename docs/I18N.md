# Internationalization

French is the **source of truth**; English is produced by AI agents editing files (no API, no key).

## Structure

- Routes: `/Codex/fr/...` and `/Codex/en/...`. The root redirects according to the browser language.
- EN pages mirror FR paths exactly: `docs/fr/a/b.mdx` ↔ `docs/en/a/b.mdx`. Slugs are never translated.
- Folder titles live in the FR `section.yml` as `title: { fr, en }`.
- Glossary and paths: `glossary/{fr,en}/<id>.md`, `paths/{fr,en}/<id>.yml`, FR used as fallback.
- Interface strings: `src/i18n/ui.ts` — the EN object is typed against FR, so a missing key fails `npm run check`.

## Missing translations

An EN route without an EN file renders the FR page with a "Translation pending" banner and `lang="fr"`
on the content, so screen readers pronounce it correctly.

## Tracking staleness

Each EN page stores `translationOf` and `sourceHash` (hash of the FR file when it was translated).

```bash
npm run i18n:status                 # missing / outdated / orphan EN pages
npm run i18n:stamp -- path/page.mdx # mark an EN page as up to date with its FR source
```

The full translation procedure for agents is in [AGENTS.md](../AGENTS.md) §4.

## Adding a language

1. Add the code to `LOCALES` in `src/config/site.ts` and an `og:locale` in `components/layout/SeoMeta.astro`.
2. Add its strings object in `src/i18n/ui.ts`.
3. Add its titles in every `section.yml` (`title: { fr, en, xx }`) and update the `sections` schema.
4. Create `src/content/docs/<xx>/` translations as needed (FR fallback otherwise).
